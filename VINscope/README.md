# VINscope — учебная демонстрация

Сайт проверяет VIN через собственный PHP API, который получает сведения из MySQL. В базе 15 вымышленных автомобилей с намеренно разным наполнением данных: у части есть записи о такси, ДТП или окрасе, у другой части некоторые источники не содержат сведений.

## Быстрый запуск

1. Создайте базу, импортировав `database.sql` через phpMyAdmin или командой `mysql -u root -p < database.sql`.
2. Скопируйте `config.example.php` в `config.php` и при необходимости укажите пароль MySQL.
3. Откройте папку через Apache в XAMPP/OpenServer либо запустите `php -S localhost:8000` в папке проекта.
4. Откройте `http://localhost:8000`.

Не открывайте `index.html` двойным щелчком: PHP API в режиме `file://` не запускается.

## VIN для демонстрации

`XTA219010G0123456`, `XW8ZZZ3CZEG000111`, `Z94CB41AAGR123456`, `WVWZZZ3CZHE000222`, `JTMBD33V405012345`, `SJNFAAJ11U1234567`.

Все записи вымышлены и предназначены только для учебной работы.

## Что добавлено для задания по scraping и бизнес-процессу

- `scraper.php` — учебный модуль скрапинга локальных HTML-источников.
- `scrape-api.php` — API, которое запускает сбор данных по VIN.
- `sources/*.html` — три полностью вымышленных источника: реестр такси, архив объявлений и страховой архив.
- На странице отчёта появилась кнопка **«Запустить скрапинг»** и блок с количеством проверенных источников, найденными записями и выделенными сигналами коммерческого использования.
- Добавлена схема бизнес-процесса: запрос → валидация → scraping → нормализация → анализ → отчёт.

Скрапинг в этой версии намеренно выполняется только по локальным учебным HTML-файлам. Это позволяет показать сам механизм HTTP/API + извлечение данных + нормализацию, не обращаясь к реальным закрытым базам или персональным данным.

### Демонстрация

1. Запустите `php -S localhost:8000` в папке проекта.
2. Откройте `http://localhost:8000`.
3. Введите, например, `XTA219010G0123456`.
4. После появления отчёта нажмите **«Запустить скрапинг»**.
5. Ниже отобразятся результаты трёх учебных источников и выявленные сигналы.

Для отчёта преподавателю можно описать архитектуру как: **Frontend → API → scraper → источники → нормализация → бизнес-правила → отчёт**.
